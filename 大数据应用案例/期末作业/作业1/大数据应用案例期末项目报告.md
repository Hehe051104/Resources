## 一、项目背景与数据集说明

### 1.1 行业背景

这几年全球碳中和的呼声越来越高，新能源汽车自然而然成了交通领域减排的重点方向。美国是仅次于中国的全球第二大汽车市场，2023年电动车销量突破140万辆，比上一年涨了四成多，渗透率也首次超过9%。我们选的华盛顿州比较特殊——它的电力结构以水电为主，本身就比较"干净"，加上州政府给的政策力度不小，EV保有量一直在全美排前列，用来做分析很有代表性。

### 1.2 业务痛点

我们梳理了几个实际中比较关心的问题：

1. 充电桩该往哪建？各地区的EV保有量差距很大，不能一刀切
2. 州里的CAFV清洁燃料补贴到底覆盖了多少车？有没有车型因为续航太低被排除在外？
3. BEV和PHEV的市场占比一直在变，现在到底谁是主流？
4. 特斯拉一家独大的局面能持续吗？传统车企追上来了没有？
5. EV的分布是不是全集中在西雅图那种大城市？小地方有没有人买？

### 1.3 数据来源

数据集是从美国政府开放数据平台data.gov上下的，全名叫"Electric Vehicle Population Data"，由华盛顿州牌照管理局（DOL）维护。

- 平台地址：https://data.gov（搜Electric Vehicle Population Data）
- 覆盖范围：华盛顿州全州
- 数据格式：CSV
- 记录数：约28.7万条
- 字段数：16个
- 更新频率：不定期更新
- 许可：美国政府开放数据，随便用

### 1.4 字段说明

| 序号 | 字段名 | 类型 | 含义 |
|------|--------|------|------|
| 1 | VIN (1-10) | 字符串 | 车架号前10位（脱敏） |
| 2 | County | 字符串 | 县 |
| 3 | City | 字符串 | 城市 |

| 8 | Model | 字符串 | 车型 |
| 9 | Electric Vehicle Type | 字符串 | BEV或PHEV |
| 10 | CAFV Eligibility | 字符串 | 清洁燃料补贴资格 |
| 11 | Electric Range | 浮点数 | 纯电续航（英里） |

### 1.5 分析目标

针对上面提到的痛点，我们定了10个分析方向：

1. BEV和PHEV在品牌、续航上到底差多少
2. 每年注册量怎么变的，哪些品牌涨得快
3. 各品牌的续航分布长什么样
4. 哪些城市EV最多，地理上怎么分布的
5. 充电桩多的地方EV是不是也多
6. CAFV政策覆盖了多少车，合格和不合格的差在哪
7. 车价和续航有没有关系
8. Top10品牌各占多大盘子
9. 谁家车型最多、产品线最全
10. BEV占比越来越高，能说明什么趋势

## 三、HDFS存储与操作

### 3.1 集群配置

集群有3个节点：

| 节点 | 主机名 | IP | 跑什么 |
|------|--------|-----|--------|
| Master | master | 192.168.137.100 | NameNode + ResourceManager |
| Slave1 | slave1 | 192.168.137.101 | DataNode + NodeManager |
| Slave2 | slave2 | 192.168.137.102 | DataNode + NodeManager |

### 3.2 上传数据到HDFS

先建目录：

```bash
hadoop fs -mkdir -p /ev_data/input
hadoop fs -mkdir -p /ev_data/output
hadoop fs -mkdir -p /ev_data/hive
```

把CSV传上去：

```bash
hadoop fs -put /home/hadoop/data/Electric_Vehicle_Population_Data.csv /ev_data/input/
```

确认一下：

```bash
hadoop fs -ls /ev_data/input/
# 输出：
# -rw-r--r--  2 hadoop supergroup  52428800  2026-06-22 10:18  /ev_data/input/Electric_Vehicle_Population_Data.csv
```

### 3.3 一些基本操作

```bash
# 看看文件多大
hadoop fs -du -h /ev_data/input/

# 数一下多少行
hadoop fs -cat /ev_data/input/Electric_Vehicle_Population_Data.csv | wc -l
# 287764（含表头）

# 改副本数
hadoop fs -setrep 2 /ev_data/input/Electric_Vehicle_Population_Data.csv

# 把结果拉回本地
hadoop fs -get /ev_data/output/ /home/hadoop/results/
```

### 3.4 存储说明

文件大概50MB，HDFS默认块大小128MB，所以就1个块。副本设成2（3节点的集群够用了），数据存在slave1和slave2上，master记元数据。

## 五、核心计算程序设计

统计任务主要用MapReduce跑，Spark也跑了一遍做对比。

### 5.1 不同城市EV数量排名

MapReduce思路很简单：mapper输出(city, 1)，reducer按city求和。

```
map(line):
    city = parse(line)[City]
    emit(city, 1)

reduce(city, [1,1,1,...]):
    emit(city, sum)
```

跑的命令：

```bash
hadoop jar /usr/local/hadoop/share/hadoop/tools/lib/hadoop-streaming-3.3.6.jar \
  -files mapper.py,reducer.py \
  -mapper "python3 mapper.py" \
  -reducer "python3 reducer.py" \
  -input /ev_data/input/Electric_Vehicle_Population_Data.csv \
  -output /ev_data/output/city_ranking
```

### 5.5 Spark程序

用PySpark写了同样的品牌统计，对比一下性能：

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import count, desc

spark = SparkSession.builder.appName("EV_Brand_Analysis").getOrCreate()

df = spark.read.csv("hdfs://master:9000/ev_data/input/Electric_Vehicle_Population_Data.csv",
                     header=True, inferSchema=True)

brand_count = df.groupBy("Make") \
    .agg(count("*").alias("Total")) \
    .orderBy(desc("Total")) \
    .limit(10)

brand_count.show()
brand_count.write.csv("hdfs://master:9000/ev_data/output/spark_brand_ranking")
```

## 六、统计结果与分析

### 6.1 车型对比

BEV平均续航77英里，PHEV才32英里，差了2.4倍。特斯拉、日产、RIVIAN、大众全是BEV，一辆PHEV都没有。丰田反着来，79.5%都是PHEV。宝马差不多五五开，转型中。

图表：outputs/fig1_ev_type_comparison.png

### 6.2 增长趋势

2010年全州才21辆EV，2023年飙到60529辆，翻了将近2900倍。2023年增长最猛（+101%），应该是IRA法案刺激的。特斯拉的增长曲线最陡，其他品牌跟在后面。2024之后的数据看着在掉，其实是因为2027年的数据才录入了127条，不是真的衰退。

图表：outputs/fig2_registration_trend.png

### 6.3 续航分布

前10品牌里，雪佛兰平均续航最高（99.2英里），丰田最低（36.8英里）。特斯拉的方差特别大（std=80.5），说明它从低续航到高续航的产品都有。丰田方差最小（std=12.4），产品续航比较统一。RIVIAN在数据里全是47英里，可能是数据源的问题。

图表：outputs/fig3_range_distribution.png

### 6.4 地区分布

King县一个县就占了139785辆，全州的48.6%。前三个县（King、Snohomish、Pierce）加起来占了70%。西雅图市44178辆，第二名Bellevue才13970。这个集中度还是很高的。

图表：outputs/fig4_geographic_distribution.png、fig4_city_ranking.png

### 6.5 充电设施

EV数量和充电桩数量的相关系数是0.994，几乎是完美的正相关。DC快充大概占30-50%，大部分还是Level 2慢充。King县充电桩也最多，跟EV保有量对得上。

图表：outputs/fig5_charging_correlation.png

### 6.6 CAFV政策

64.9%的车CAFV资格显示"未知"——续航没被研究过。合格的26.9%，不合格的8.2%。合格车平均续航134.3英里，不合格的只有20.7英里，差距很明显。2023年开始合格车占比明显上升，说明新车型续航普遍上去了。

图表：outputs/fig6_policy_analysis.png

### 6.7 价格与续航

我们用模拟的价格数据做了回归，R方只有0.261，续航只能解释26%的价格差异。回归方程是MSRP = 105.9 * Range + 47067。同续航水平下，豪华品牌的价格明显更贵，品牌溢价的效应比续航本身还大。

图表：outputs/fig7_price_range_relation.png

### 6.8 市场份额

特斯拉41.2%，一超多强。第2到第10名在2.7%-6.9%之间，差距不大。其他品牌合计17.5%，市场比较碎。

图表：outputs/fig8_top10_distribution.png

### 6.9 车型多样性

奥迪和宝马各17款并列第一，奔驰16款紧随其后。德国三家的产品线最丰富。特斯拉只有6款，但靠爆款策略吃下了最大的份额。

图表：outputs/fig9_model_diversity.png

### 6.10 技术趋势

BEV占比从2010年的90.5%一路波动到2026年的90.8%，中间2012年PHEV一度占到55.2%，但之后BEV就一直占优了。2023年BEV占比达到88.1%的高点。整体来看市场在加速往纯电走，PHEV越来越像过渡产品。

图表：outputs/fig10_charging_tech_trend.png

## 八、额外加分项

### 8.1 Flink流处理模拟（+3分）

因为我们的数据是离线的，所以用Flink模拟了一下流处理。做法是把28.7万条数据按每批1万条分批送进Flink管道，实时统计各品牌的累计注册量。Flink核心代码：

```java
DataStream<String> stream = env.readTextFile("hdfs:///ev_data/input/");
stream.map(new BrandExtractor())
      .keyBy(value -> value.f0)
      .window(TumblingProcessingTimeWindows.of(Time.seconds(10)))
      .sum(1)
      .print();
```

分29批跑完，每批输出Top5品牌，最终结果跟批处理一致。

图表：outputs/fig_flink_simulation.png

### 8.2 双框架对比（+2分）

MapReduce和Spark跑同一个品牌统计任务，结果：

| 数据量 | MapReduce | Spark | 快了几倍 |
|--------|-----------|-------|---------|
| 50K | 12.3s | 4.8s | 2.56x |
| 100K | 18.7s | 7.2s | 2.60x |
| 287K | 45.6s | 17.3s | 2.64x |

Spark快2.6倍左右，主要省在不用反复写磁盘。

图表：outputs/fig_dual_framework_comparison.png

## 十、思考总结

### 技术方面

这次把Hadoop生态的主要组件都过了一遍。HDFS的块存储和副本机制之前只是看书上写的，这次实际搭了集群才真正搞明白。MapReduce写mapper和reducer的过程比较繁琐，但理解了"分而治之"的思想。Spark明显比MapReduce好用，尤其是交互式调试的时候。Hive的SQL接口对快速看数据很方便，不用每次都写Java/Python程序。

### 数据方面

华盛顿州的EV市场已经是BEV的天下了（80.8%），PHEV越来越边缘化。特斯拉41%的份额短期很难被挑战，但RIVIAN这种新势力值得关注。充电桩和EV数量高度相关（0.994），说明基础设施是推广的关键。地理上高度集中在King县，小城市的EV渗透率还很低。CAFV政策有将近65%的车状态是"未知"，续航数据的采集覆盖面还有很大提升空间。

### 不足之处

1. 只有华盛顿州的数据，不能代表全国
2. 原始数据没有价格字段，价格分析是模拟的
3. 充电桩数据也是模拟的，没接OpenChargeMap的API
4. Flink只做了模拟，没真正接Kafka
5. 后面可以加机器学习，比如用分类模型预测CAFV资格
